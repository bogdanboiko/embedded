B1: Демо 1 (кільцевий буфер): змініть RB_SIZE на 4.

 - Скільки push пройде до FULL?
 - 3 push, адже 1 зарезервований щоб відрізняти FULL і EMPTY стани кільцевого буферу.

Потім зробіть кілька push, два pop і ще push — поясніть з виводу, як індекси «обертаються по колу».

Кільцевий буфер складається з масиву, head і tail значень які вказують на поточні індекси: 
head - на індекс після останнього доданого елемента, а tail - на перший доданий в черзі.
Коли head або tail доходять до кінця масиву, їх індекс перескакує на початок, таким чином
уникаючи необхідності зміщення всіх елементів коли head індекс дійшов до кінця масиву. 
Через кільцевий буфер реалізується механізм FIFO.

В4. Демо 4 (константи): 
(а) приберіть const у gamma_lut — у який сегмент переїде адреса? 

В сегмент .data(у flash пишуться ініт дані, в ram актуальні дані змінної)

0x3fc8fdec - 1070136812
.data - 1070136812

(б) спробуйте оголосити масив розміром const int N = 4; — що скаже компілятор? 

Помилка. Атрибут const не робить змінну доступною для compile time. const робить змінну
read only константою доступною в рантаймі. Зберігається у flash/.rodata.

Замініть на #define або enum.

#define це макрос для компілятора, отже під час компіляції компілятор підставляє ці значення
в код. enum також compile time об'єкт, тому через enum це також можливо зробити.

Переваги enum перед #define: enum type safe, макроси нічого не знають про с код або якісь типи,
просто заміна тексту;
